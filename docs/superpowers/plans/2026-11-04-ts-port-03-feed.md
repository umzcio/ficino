# TS Port 03 — Retrieval, Search, Feed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the feed generator and everything it stands on. That means hybrid retrieval, the rerank providers,
the persona library and prompts, `generate_feed`, a fixed `regenerate_post`, the alert and preference jobs, the
`/feed` routes (including the `/feed/status` job-state mapping) and `/search`. After this plan, a user with
processed papers can generate, append to, regenerate in and search a persona feed, with no Python, Celery or
Redis involved.

**Architecture:** The worker gains five handlers: `generate_feed`, `regenerate_post`, `check_contradictions`,
`check_post_feed` and `compute_preferences`. Plan 02 already enqueues two of them (`check_contradictions` and
the auto-generate `generate_feed`), and those jobs have been waiting with no consumer.

The feed code lives in `src/feed/`:
- `personas.ts`: the persona library, its pure helpers and the planner.
- `prompts.ts`: prompt text.
- `llmPost.ts`: LLM post parsing, validation and the contradiction classifier.
- `retrieval.ts`: hybrid SQL plus rerank.
- `slots.ts`: per-slot chunk budgeting and post finishing.

The job orchestration lives in `src/tasks/`. Every random choice goes through an injected `Rng`, so tests are
deterministic. Personas are loaded from the DB once per job, not cached per process.

**Tech Stack:** Plan 01 and plan 02 dependencies only. **No new npm dependencies.** uuid5 is about 15 lines over
`node:crypto` sha1.

## Deliberate changes from Python (each pinned by a test)

1. **`regenerate_post` on a figure post works** (spec "Known bugs"). It re-uses the post's own figure (looked up by
   `figure_id`, scoped to the owner) and builds a figure prompt. If the post has no `figure_id`, or the figure no
   longer exists, it regenerates as a `post`. Python always raised. Task 9.
2. **Retrieval never mixes embedding models** (spec anti-goal). Every retrieval statement only considers chunks
   whose `metadata->>'embed_model'` equals `embedModelId(providers)`. `generate_feed` and `regenerate_post` log one
   warning, `embed_model_mismatch {expected, excluded_chunks}`, when any in-scope chunk was skipped. Python silently
   compared vectors from different models. Task 6.
3. **Personas load once per job** instead of from a per-process cache with a 1 h TTL. Edits apply on the next job.
   Task 2.
4. **A first author that is empty or whitespace-only** is treated like `unknown`: the short cite falls back to the
   title. Python's `"  ".split()[-1]` raised `IndexError` outside the per-slot `try`, which failed the whole feed.
   Task 2.
5. **`rerank_provider = local`** (the dropped cross-encoder) widens the SQL pool and then passes the results
   through, with a `rerank_local_unavailable_passthrough` warning. This is what the shipped Python image did,
   because `sentence-transformers` was never installed. Task 5.
6. **Job ids are pg-boss ids.** Any throw from `generate_feed` is retried by pg-boss, including the idempotency reads
   that sit before Python's `try`, which Celery did not retry. Task 8.

## Review Focus

1. **Two users' feeds at the same time never cross keys or papers.** A's and B's `generate_feed` run concurrently in
   one worker. Every LLM and embed call for A's feed carries A's resolved key and model. A's feed cites only A's
   papers, and B's feed only B's. Pinned in Task 8.
2. **A retried feed job never duplicates posts.**
   - A fresh `generate_feed` that fails after its INSERT and is retried with the same job id returns the same
     `feed_id` with no second row.
   - An append-mode retry doesn't append twice.
   - `/feed/status` shows `retry` during the retry delay and `complete` after it.

   Pinned in Tasks 8 and 12.
3. **Garbage LLM output never becomes a post.** Each of these drops only that slot, and the feed completes with
   the other posts:
   - prose with no JSON (wrapped as a plain post, as in Python)
   - a bare JSON string or array (dropped)
   - a 4001-code-point blob (dropped)
   - the preamble's `{"posts":[…]}` shape, which has no `content` (dropped)

   Pinned in Tasks 4 and 8.
4. **Stored chunks from another embedding model are never returned.** A corpus where one paper's chunks are tagged
   with a different `embed_model` (or untagged) gets no chunks from that paper by vector or keyword, and the job
   logs `embed_model_mismatch`. Pinned in Tasks 6 and 8.
5. **`/feed/status` never 500s and never leaks internals.**
   - A non-UUID id and an unknown UUID return `pending`.
   - A cancelled job returns `revoked`.
   - A failed job's `error` is the exception message only, with no stack and no `name`.

   Pinned in Task 12.
